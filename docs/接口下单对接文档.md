# 接口下单直发算力券 对接文档

面向第三方系统的机器对机器（M2M）接口。绕过支付，直接下单并异步生成算力券兑换码（卡密），通过查询接口获取卡密与生成状态。

---

## 1. 接入前置

### 1.1 申请开通
- 由平台方在 `INTERFACE_ORDER_ALLOWED_USER_IDS` 配置中加入调用方的 `user_id`（白名单）。
- 调用方在平台前端或开放平台后台**自行创建一个 API Key**，记下明文 `sk_xxx`（仅创建时可见，丢失需重建）。

### 1.2 鉴权方式
所有请求必须携带请求头：

```
X-API-Key: sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

- API Key 与所属 `user_id` 一一绑定。
- 请求参数中的 `user_id` 必须与 `X-API-Key` 所属用户一致，否则返回 `403`。
- `user_id` 必须在白名单内，否则返回 `403`。

### 1.3 限流
| 接口 | 维度 | 阈值 |
|---|---|---|
| 创建下单 | 单 API Key | 60 次/分钟 |
| 创建下单 | 单 IP | 200 次/分钟 |
| 查询状态 | 单 API Key | 120 次/分钟 |
| 查询状态 | 单 IP | 300 次/分钟 |

超限返回 `429 Too Many Requests`。

### 1.4 环境地址
- 测试：`https://lychee.thinkarts.cn/new-api-test/` 后端服务地址由平台方提供（示例中用 `http://127.0.0.1:8888`）。
- 生产：由平台方单独提供。

## 3. 接口下单

### 请求
```
POST /api/interface/order/create
Content-Type: application/json
X-API-Key: sk_xxx
```

```json
{
  "user_id": 13,
  "sku_id": 1,
  "quantity": 2,
  "client_order_no": "C-20260702-001"
}
```

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| user_id | int | 是 | >0 | 必须与 X-API-Key 所属用户一致，且在白名单内 |
| sku_id | int | 是 | >0 | 平台 SKU ID |
| quantity | int | 是 | 1~100 | 下单数量，即应生成卡密总数 |
| client_order_no | str | 是 | 1~64 字符 | 客户侧订单号，仅作记录，不做幂等校验 |

### 响应
```json
{
  "success": true,
  "message": "下单成功，兑换码生成中，请用查询接口获取卡密",
  "order_no": "E7F53E6AECE241B5",
  "client_order_no": "C-20260702-001"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| success | bool | 调用状态。`true`=下单成功；`false`=业务校验失败（如 SKU 不存在） |
| message | str | 结果描述 |
| order_no | str \| null | 平台订单号，**用于后续查询卡密**。下单失败时为 null |
| client_order_no | str \| null | 回显客户侧订单号 |

### 关键语义
- **异步生成**：本接口创建订单后立即返回 `order_no`，**不等待卡密生成**。兑换码在后台异步生成，调用方需轮询查询接口获取。
- **不做幂等**：`client_order_no` 仅作记录字段，同一 `client_order_no` 可重复下单，每次都会创建新订单。
- **失败语义**：仅业务校验失败（SKU 不存在/下架、白名单、鉴权）返回 `success=false`。订单已建即视为下单成功。

### 常见错误
| HTTP | message | 原因 |
|---|---|---|
| 401 | 缺少 X-API-Key | 未带请求头 |
| 401 | 无效的 API Key | key 错误/已删除 |
| 401 | API Key 已禁用 / 已过期 | key 状态异常 |
| 403 | API Key 与 user_id 不匹配 | 用 A 的 key 传了 B 的 user_id |
| 403 | 该用户无接口下单权限 | user_id 不在白名单 |
| 429 | rate limit exceeded | 触发限流 |
| 200 | success=false, message="SKU 不存在或已下架" | sku_id 无效 |

## 4. 查询订单状态

### 请求
```
GET /api/interface/order/status?user_id=13&order_no=E7F53E6AECE241B5
X-API-Key: sk_xxx
```

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| user_id | query | int | 是 | 必须与 X-API-Key 所属用户一致 |
| order_no | query | str | 是 | 创建接口返回的平台订单号 |
| X-API-Key | header | str | 是 | 鉴权 |

### 响应
```json
{
  "success": true,
  "message": "查询成功",
  "order_no": "E7F53E6AECE241B5",
  "order_status": "success",
  "order_status_text": "生成成功",
  "total": 2,
  "codes": ["1185f8c2bd0740dfac9cce044f4d7ffd", "abc123..."]
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| success | bool | 调用状态 |
| message | str | 结果描述 |
| order_no | str | 平台订单号 |
| order_status | str | 订单级聚合生成状态，见下表 |
| order_status_text | str | 状态中文描述 |
| total | int | 应生成卡密总数（订单项数量） |
| codes | list[str] | **仅 `order_status=success` 时返回全部卡密，其他状态为空数组** |

### order_status 取值
| 值 | 中文 | 含义 | codes |
|---|---|---|---|
| `generating` | 生成中 | 兑换码尚在生成（含部分已生成但未全部完成） | `[]` |
| `failed` | 生成失败 | 任一订单项生成失败 | `[]` |
| `success` | 生成成功 | 全部订单项均生成成功 | 全部卡密 |

> 聚合规则：任一订单项 `redemption_status==3` → `failed`；全部 `==2` → `success`；其余 → `generating`。

### 常见错误
| HTTP | message | 原因 |
|---|---|---|
| 401 | 缺少 X-API-Key / 无效的 API Key | 同上 |
| 403 | API Key 与 user_id 不匹配 / 该用户无接口下单权限 | 同上 |
| 404 | 订单不存在或不属于当前 API Key 所属用户 | order_no 错误或跨用户 |
| 422 | validation error | 参数缺失/类型错误 |
| 429 | rate limit exceeded | 触发限流 |

## 5. 调用流程建议

```
1. 调用方: POST /create  → 拿到 order_no
2. 调用方: 轮询 GET /status?order_no=...
   - order_status=generating → 等待，间隔建议 1~2s
   - order_status=success    → 取出 codes，结束
   - order_status=failed     → 整单失败，联系平台方排查（已生成的码会被作废）
3. 超时策略：建议总轮询时长 30s，仍未终态则视为超时，落库待对账
```

## 6. 调用示例

### 6.1 cURL
```bash
# 创建下单
curl -X POST http://127.0.0.1:8888/api/interface/order/create \
  -H "X-API-Key: sk_xxx" \
  -H "Content-Type: application/json" \
  -d '{"user_id":13,"sku_id":1,"quantity":2,"client_order_no":"C-20260702-001"}'

# 查询状态
curl -G http://127.0.0.1:8888/api/interface/order/status \
  -H "X-API-Key: sk_xxx" \
  --data-urlencode "user_id=13" \
  --data-urlencode "order_no=E7F53E6AECE241B5"
```

### 6.2 Python (httpx)
```python
import httpx, time

BASE = "http://127.0.0.1:8888"
HEADERS = {"X-API-Key": "sk_xxx", "Content-Type": "application/json"}

# 1. 下单
resp = httpx.post(
    f"{BASE}/api/interface/order/create",
    headers=HEADERS,
    json={"user_id": 13, "sku_id": 1, "quantity": 2,
          "client_order_no": "C-20260702-001"},
    timeout=10,
)
data = resp.json()
if not data["success"]:
    raise RuntimeError(data["message"])
order_no = data["order_no"]
print(f"order_no={order_no}")

# 2. 轮询查询卡密
codes = []
for _ in range(30):
    r = httpx.get(
        f"{BASE}/api/interface/order/status",
        headers=HEADERS,
        params={"user_id": 13, "order_no": order_no},
        timeout=10,
    ).json()
    if r["order_status"] == "success":
        codes = r["codes"]
        break
    if r["order_status"] == "failed":
        raise RuntimeError(f"生成失败: {r}")
    time.sleep(1)

print(f"codes={codes}")
```

### 6.3 Java (OkHttp) — 仅下单
```java
OkHttpClient client = new OkHttpClient();
String body = "{\"user_id\":13,\"sku_id\":1,\"quantity\":2,\"client_order_no\":\"C-001\"}";
Request req = new Request.Builder()
    .url("http://127.0.0.1:8888/api/interface/order/create")
    .header("X-API-Key", "sk_xxx")
    .header("Content-Type", "application/json")
    .post(RequestBody.create(body, MediaType.parse("application/json")))
    .build();
try (Response r = client.newCall(req).execute()) {
    System.out.println(r.body().string());
}
```

### 6.4 Node.js (axios)
```javascript
const axios = require('axios');
const BASE = 'http://127.0.0.1:8888';
const headers = { 'X-API-Key': 'sk_xxx' };

// 下单
const { data } = await axios.post(`${BASE}/api/interface/order/create`, {
  user_id: 13, sku_id: 1, quantity: 2, client_order_no: 'C-001'
}, { headers, timeout: 10000 });
const orderNo = data.order_no;

// 轮询查询
let codes = [];
for (let i = 0; i < 30; i++) {
  const r = await axios.get(`${BASE}/api/interface/order/status`, {
    headers, params: { user_id: 13, order_no: orderNo }, timeout: 10000
  });
  if (r.data.order_status === 'success') { codes = r.data.codes; break; }
  if (r.data.order_status === 'failed') throw new Error('生成失败');
  await new Promise(r => setTimeout(r, 1000));
}
console.log(codes);
```

## 7. 字段对照（订单模型，供对账参考）
| 字段 | 含义 |
|---|---|
| `orders.order_no` | 平台订单号（16 位 hex 大写） |
| `orders.pay_channel` | 支付渠道，本接口固定 `3`=接口调用 |
| `orders.status` | 订单状态，本接口固定 `1`=已支付 |
| `orders.client_order_no` | 客户侧订单号 |
| `order_items.redemption_status` | 兑换码状态：0=待生成, 1=生成中, 2=已生成, 3=生成失败 |
| `order_items.redemption_code` | 兑换码（卡密），仅 `2` 时有值 |
